# 2026-09-19 馬主関連ヒートマップ3列

## 仕様

調教師の直後に、以下の順序で追加。

| 列                   | 集計範囲                                                               |
| -------------------- | ---------------------------------------------------------------------- |
| 馬主・同場レース30年 | 同じ馬主ID、同じ競馬場、直前30年間、出走予定レースと同じ馬場種別       |
| 騎手×調教師×馬主30年 | 同じ3者のID、JRA・地方の全場、直前30年間、出走予定レースと同じ馬場種別 |
| 馬主                 | 既存の同条件レース検索・フォールバックと同じ対象レース内の馬主集計     |

30年の2列は同条件検索の距離・クラス等に依存しない。芝・ダート・障害・サンド・ばんえいを分離し、当日以降は除外。確定着順が正の出走を分母とし、1着・2着以内・3着以内をそれぞれ勝率・連対率・複勝率の分子にする。表示は小数1桁、出走0件は0%。ID不明を架空の0件扱いにはしない。

30年のSQLは対象日の出走馬に関係する馬主・組み合わせへ絞り、無関係な全履歴の集計結果をキャッシュへ取り込まない。組み合わせ列はJRA/NAR履歴をUNION ALLし、各履歴のRAで種別を判定する。対象組み合わせは開催場を限定せず共有する。

## 実装

- Catalog: `heatmap-partnership.ts` / `heatmap-partnership-sql.ts` / `heatmap-partnership-stats.ts` を拡張。
- Viewer: 列・表示モデル、パートナーシップ行の読み取り、列別キャッシュ、同条件Catalog要求の `includeOwner` を拡張。
- 表示キャッシュを `pc-keiba-viewer:win-rate-heatmap:v22`、列フラグメントを20種類に更新。旧地域キャッシュを参照しない。全46レースの検証済み世代を事前配置してから切り替えた。
- 全場組み合わせの集計キャッシュキーは `jockeyTrainerOwner-all-sources`。単一ソースだけの途中キャッシュを再利用しない。
- 表示モード4種類 × レース数表示2種類 × 血統分離2種類の16表示バリアントを生成。
