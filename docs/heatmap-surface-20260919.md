# 2026-09-19 ヒートマップ勝率の馬場種別修正

## 結果

本番の **全46レース・514頭・対象2列1,028セル** を修正・検証済み。
通常の表示API（warmパラメーターなし）は全件 `200 / HIT`。
各セルの出走数・勝利数・勝率が、別途読み取り専用で実行した履歴集計と一致した。

## 原因と変更

- `騎手・同場3年` / `騎手×調教師・同場10年` の履歴SQLに馬場種別の条件がなく、同日・同場の集計キャッシュも種別を区別していなかった。
- 対象レースのRAメタデータから種別を決定し、同場かつ同種別の履歴だけを集計する。類似レース検索のオプションには依存しない。
- 芝・ダート・障害を分離。サンド・ばんえいも独立した種別として扱う。種別不明・競合時は混合集計や架空のゼロを返さない。
- 3年 / 10年の期間、当日以降の除外、確定着順が正の出走のみを数える条件は維持。`馬×騎手` の通算集計は従来どおり全種別。
- 集計キャッシュを `heatmap-partnership-v2` に更新し、キーに種別を追加。
- 表示キャッシュを `pc-keiba-viewer:win-rate-heatmap:v20` に更新。旧地域キャッシュを読まないようにし、全46レースの新しい世代を事前作成してからViewerを切り替えた。

## 検証

- 読み取り専用PostgreSQLトランザクションで対象全頭を独立再集計。RA/SEのレースキー結合、重複出走の排除、種別・競馬場・期間別の勝利数 / 出走数を照合。
- キャッシュ再生成後に通常の表示APIを取得し、独立集計と照合。
- 新名前空間への転記時にも表示データと対象2列のフラグメントを照合。
- Viewer切替後、全46レースを通常の表示APIで再検証。
- 芝・ダート・障害・ばんえい・地方ダートの代表5ページと静的JSアセットが200で取得できることを確認。ブラウザーの画面操作テストではなくHTTP配信検証。

例：阪神1R・1番の騎手同場3年は、全種別 **29勝 / 403走 = 7.2%** から、ダートのみ **21勝 / 224走 = 9.4%** に修正。
阪神2R・1番は、全種別 **12勝 / 176走 = 6.8%** から、芝のみ **5勝 / 92走 = 5.4%** に修正。
